# Gu Game Remastered

A new Discord game, built from scratch. Shares nothing with the original
`Gu/GuGame` — no code, no data, no schema.

**Stack:** Python + discord.py, PostgreSQL, deployed on Railway.

---

## Database

The schema is defined by the `.sql` files in `db/migrations/`. They are the
source of truth — there is no ORM and nothing is autogenerated. You write the
DDL; the runner applies it once, in order, and records that it did.

### Rules

1. **Migrations are forward-only.** Once a file has been applied anywhere, it is
   frozen. Need a change? Write a new migration. The runner stores a checksum of
   every applied file and refuses to run if one was edited underneath it.
2. **Filenames are `NNNN_lower_snake_case.sql`.** The number is the version and
   sets the apply order. A file that does not match is a hard error, not a skip —
   a typo that silently never runs is the worst possible failure here.
3. **Each migration runs in its own transaction.** Postgres DDL is
   transactional, so a migration that fails part way leaves nothing behind, and
   the ones before it stay applied.

### Commands

```bash
python -m db.migrate status     # what is applied, what is pending
python -m db.migrate up         # apply everything pending
python -m db.migrate new <name> # scaffold the next numbered file
python -m db.migrate verify     # non-zero exit on drift or pending work (CI)
```

`up` runs automatically on every Railway deploy via the `release` line in
`Procfile`, and takes a Postgres advisory lock so two instances deploying at
once cannot both migrate.

### Schema conventions

These hold across every table. They are the deliberate corrections to how the
original game's database grew:

| Convention | Why |
|---|---|
| Surrogate `<thing>_id` primary keys | The Discord snowflake appears in exactly one column in the whole database, not copied into every child table as an unconstrained `BIGINT`. |
| `TIMESTAMPTZ`, never epoch integers | Postgres does the date arithmetic; `now()` is the default instead of something every caller computes. |
| Every FK declared, every FK indexed | Postgres indexes the referenced side automatically but never the referencing side — an unindexed FK makes the parent's delete scan. |
| `CASCADE` for dependent rows, `RESTRICT` for history | Losing a player should not quietly erase the audit trail of what was done to them. |
| `JSONB` only for open-ended payloads | Anything ever filtered, sorted, or summed gets a real column. |
| Features extend sideways, not wider | New systems add tables. `players` holds identity and is finished — this is what stops it becoming a 120-column table again. |

## Local setup

```bash
python -m pip install -r requirements.txt
cp .env.example .env       # then fill it in
python -m db.migrate up
```

There is no local Postgres on this machine and no Docker. Point `DATABASE_URL`
at the Railway instance's **public** URL for development — in the Railway
dashboard, Postgres service → Variables → `DATABASE_PUBLIC_URL`. (The internal
`DATABASE_URL` only resolves from inside Railway's network.)

## Layout

```
db/
  connection.py            # the one place that reads DATABASE_URL
  migrate.py               # the migration runner
  migrations/
    0001_foundation.sql    # players, audit log, shared conventions
```
